# 夸克云存档：开发状态与验证

云端沿用 format=1 协议，可与 Windows 工具互通；真实账号和具体游戏的跨平台存档兼容性需要设备联调。

## 页面

- 首页：登录夸克 → 原生弹窗显示本地生成的二维码；登录后优先显示夸克昵称，未返回昵称时显示用户 ID；账号详情保留 ID，可退出登录。账号隔离仍使用稳定的用户 ID。
- 游戏页：本地存档时间下方显示云端时间、上传时间，启动前自动云同步及退出自动上传分别设置、默认关闭，以及两个方向的同步按钮。
- 游戏页识别失败：查找存档位置 → 开始 → 进入游戏保存 → 退出 → 完成查找 → 勾选候选文件并使用。
- 收起 Decky 侧栏关闭全部插件弹窗；网络任务在后端运行，不依赖弹窗存活。页面重新打开时显示任务结果。插件不使用系统通知。

## 启动前云同步与游戏分组

开启“开始游戏前自动云同步”后，插件在 Steam 游戏模式的 `SteamClient.Apps.RunGame` 启动请求处等待后端检查。内容一致直接启动，云端有新进度且本地仍是上次同步内容时，先下载并保留覆盖前备份再启动。云端未变化而本地有新进度时保留本地；两端同时变化或首次同步存在不同内容时暂停并提示手动选择方向。网络、路径、登录错误也暂停，用户可取消启动，或明确选择使用当前本地存档启动。插件不写入 Deck 通知。

开关按夸克账号、Steam 账号及游戏隔离。同步期间切换账号、取消启动、重复点击或卸载插件不会继续旧的启动请求。仅从 Steam 游戏模式的上述入口发起启动可以拦截；桌面模式外部命令行或其他入口不在此保证范围内。

游戏列表隐藏 Proton、GE-Proton、Steam Linux Runtime 等兼容层。读取本地 Steam `appinfo.vdf` v27/v28/v29 元数据，先显示不支持 Steam 云存档的游戏，再显示支持的游戏；缺失元数据归为待确认。两组都可使用夸克云同步，分组不依据是否有存档文件或是否启用 Steam 云同步。

## 归档格式

云端目录：`/UmeYc-SteamBack/<Steam Account ID>/<游戏 App ID>/`。夸克账号本身提供网盘空间隔离。

每个游戏仅保留最新一份云端存档，包括一个 ZIP 和一个 JSON 索引。先上传 ZIP，确认夸克已列出完整文件，再上传版本索引；再次读取确认最新索引及对应 ZIP 可见后，清理同步开始前已存在的旧版本。内容相同时不重复上传，但也执行历史清理。上传失败时不清理已有版本。清理失败显示提示，下次成功上传时重试。

清理仅匹配当前游戏目录内插件生成的 `version-<时间>-<随机ID>.json/.zip` 普通文件，不处理其他文件、目录或其他账号/游戏。先确认旧索引删除完成，再删除对应旧 ZIP；删除在夸克端延迟完成时会等待确认。未发布索引的孤立 ZIP 只在服务端创建时间超过 24 小时后清理，避免误删其他设备正在上传的文件；因此中断上传或清理失败时可能暂有多余文件。使用夸克文件删除接口，不清空账号回收站，回收站空间按夸克自身规则释放。

ZIP 不保存另一设备的绝对恢复路径。清单记录相对路径、来源目录序号、大小、修改时间与 SHA-256。下载校验外层 ZIP 摘要、内部文件摘要、账号、游戏和目录映射后，才导入本地备份并执行带撤销备份的恢复。自选路径需在不同 Deck 上按对应顺序配置，且目标文件必须位于用户当前选择的范围。

本地列表保留“云端下载”记录，保存本次下载的云端内容；覆盖前的本地进度单独保留为“同步前本地备份”，两者均可恢复或手动删除。普通恢复产生“恢复前本地备份”。旧版未记录来源的撤销备份显示“覆盖前本地备份”，不猜测其来源，不修改旧文件或用户自定义名称。

源文件修改时间用于“云端存档时间”，上传时间单独记录。相同内容不重复上传。云端有未同步的不同版本时要求显式确认；上传期间再次检查是否有其他设备发布，冲突时不发布索引。夸克网页接口不提供跨设备原子比较更新，因此极端并发不能完全避免两个版本同时发布，清理前发现最新版本变化会跳过删除，后续同步仍会检测内容差异。同步开始后出现的其他设备文件不会纳入本次清理。

单次上传及解压文件总量上限 2 GiB，最多 50,000 个文件。不会跟随所选目录内的符号链接。下载期间游戏重新启动或 Steam 账号切换时，不覆盖当前游戏文件。

自动上传通过插件全生命周期的后台游戏状态观察器触发，检测到运行 → 退出后，等待两次一致的文件状态再上传，最多等待约 30 秒。没有开启的游戏不上传；启动时已经关闭的游戏不补传。自动任务排队，内容无变化时跳过。需要 Steam/Decky 正常运行；系统直接断电或强制停止插件无法保证上传完成。

## 凭证

- `quark/session.cookies`：后端会话文件，0600 权限，目录 0700；不返回前端、不写入云存档、不打印到日志。
- `quark/identity.json`：最近成功验证的夸克用户 ID，用于恢复后台开关作用域；实际同步前仍验证登录。
- `cloud_settings.json`：按夸克用户、Steam 账号、游戏保存自动上传开关和最近同步摘要。
- `cloud_activity.json`：最近任务结果；关闭并重开页面后可查看。
- 嗅探基线只在插件进程内保存，重启插件后需重新开始。

协议适配参考公开实现所展示的网页端请求格式：[Quark CLI](https://github.com/imeiming/quark-drive)。未使用外部二维码服务，不依赖夸克 TV 只读接口。网页端接口可能随夸克升级变化，真实扫码、Cookie 刷新、分片上传和下载域名需在联调时确认。

## 本地验证

54 项 Python 测试和 15 项前端宿主测试通过。测试全部使用临时文件及模拟夸克接口，没有访问真实网盘或游戏存档。

覆盖：二维码状态与私有会话保存、分页目录、秒传确认、分片签名与 Cookie 隔离、HTTP 错误脱敏、云端完整往返、文件时间保留、撤销恢复、多设备路径映射、冲突确认、上传失败保留旧版本、摘要损坏、ZIP 路径穿越与符号链接、精确文件范围、账号隔离与切换、游戏运行保护、退出上传默认关闭与去重、异步任务、嗅探新增及修改候选和范围上限。

## Deck 回到内网后的实机清单

1. 安装开发包前记录现有数据摘要，安装后核对未变化。
2. 夸克真实扫码，确认用户 ID，关闭全部页面并重启 Decky，验证会话及默认开关。
3. 使用独立测试游戏和临时存档路径完成上传、查看网盘根目录、下载、恢复及撤销，核对内容和两个时间。
4. 验证夸克秒传、普通分片上传、断网和过期登录；失败不应被显示为成功。
5. 每游戏开关默认关闭；仅开启的测试游戏退出后自动上传，重启游戏取消上传。侧栏关闭仍能执行，页面重开可查看结果。
6. 在独立目录模拟云端不同版本，确认冲突提示、新版成功后旧版清理、失败时保留上一份，以及内容不变时清理旧历史，不对用户真实游戏执行覆盖测试。
7. 实际启动一个无自动路径的游戏，保存并退出，确认嗅探候选和手柄选择流程。
8. 核对全部新增弹窗手柄导航、侧栏收起关闭、无系统通知；确认后再按用户指令发布。
